# Rotation Engine — Phase 2 Implementation Notes

Scope: spec sections **10–20** of `rotation_engine_spec.md`, plus the "Cross-cutting notes" section. Builds on Phase 1 (sections 0–9, see `PHASE1_NOTES.md`).

All work was done in place in `/home/user/workspace/rotation-engine/app.html` (single-file React 18 UMD + Babel + Tailwind CDN + SheetJS app, no build step). `index.html` is kept byte-identical to `app.html`.

## What was implemented

**§10 — Sent-home memory exclusion (opt-in, default include)**
- `actualEntries()` now includes sent-home rows in rotation memory by default. A row is skipped only when `out.status==="sent_home" && out.excludeFromMemory===true`.
- The **"Exclude from memory"** toggle (already present as Phase‑1 groundwork) lives on the EOD Closeout page per staff row, only shown when status is `sent_home`, defaults OFF — verified in QA.

**§11 — Manual historical/archive board creation**
- New "**+ ADD HISTORICAL BOARD**" action on the Archive tab opens a form: date, side, a searchable repeatable staff+assignment row picker, and a required justification textarea.
- Saving (`saveManualHistoricalBoard`) creates a shift record directly in `shifts` with `manual_entry:true`, `justification:<comment>`, entries tagged `override_type:"manual_historical"`, and marks it immediately closed (`eod:{closed:true, closed_by, closed_at, notes:<justification>}`) — the simpler, backfill-oriented path recommended in the spec. The justification is stored both on the shift record and echoed into the handoff notes and (implicitly) into each entry's `reason`.

**§12 — Deficiency review inline assign/reassign with comments**
- New shared `DeficiencyAssignRow` component: a staff picker (filtered to `eligible()`, not-yet-placed on that board/shift) + required comment box, that on submit creates an entry with `override_type:"deficiency_assignment"`, `reason:<comment>`.
- Reused verbatim on both the unsaved Generated Board's Deficiency Review panel (`assignPendingDeficiency`, mutates `pending` only) and the new Current Shift compliance panel (`assignShiftDeficiency`, mutates the saved shift).
- Only wired for `unfilled` deficiencies (per spec's literal `kind==="unfilled"` gate in `DeficiencyAssignRow`); the "also works as REASSIGN for a flagged wildcard/override entry" extension was **not** built as a separate reassign-specific UI in this pass — see Assumption 1.

**§13 — Compliance recheck on Current Shift**
- New "**RUN COMPLIANCE CHECK**" button + panel on Current Shift (`CurrentShiftEntries`). Recomputes deficiencies from the shift's **live** entries via the shared `recomputeDeficiencies()` helper (new — derives `core`/`used`/`secondaryIds` straight from `entries`+`catalog`+`closedIds` so this reuses `computeDeficiencies()` without re-running `runEngine`).
- Zero issues → green "✓ GOOD TO GO" banner. Issues → same severity/description styling as Deficiency Review, each `unfilled` row gets the §12 assign control inline.
- Read/evaluate only — never regenerates the board or erases redistribution history. Appends to an **append-only** `shift.complianceChecks:[{timestamp,by,result,issueCount}]` log rendered chronologically underneath.
- **Mid-shift room closures**: same "CLOSE ASSIGNMENTS" control as board generation, now also on Current Shift (`toggleRoomClosure` / `midShiftClosed` component-local state, intentionally **not** persisted to `shifts` — see Assumption 2), feeding into `intentionallyClosedIds` so a closed room's coverage need is never double-flagged as unfilled, and remains available as a combine target/source per §4.

**§14 — Sortable Current Shift / Archive roster view**
- New `SortableRosterHeader` + `sortRosterEntries()` shared by both Current Shift and Archive's closed-shift detail view. Default: start-time ascending, then `staff_name` alphabetically. Clicking a header sets `sortBy` and toggles asc/desc on repeat clicks (▲/▼ glyph, bold+teal active column). An unset/reset `sortBy` falls back to the default ordering.

**§15 — Editable generated board before saving**
- `PendingEntryRow` now renders an inline assignment `<select>` per row (respecting `eligible()`, showing taken-by-someone-else assignments as "(covered)") wired to `reassignPendingEntry`, which mutates `pending.entries` in place (no engine re-run) and recomputes `pending.deficiencies` live via the new `recomputeDeficiencies()` helper.

**§16 — Excel import (roster) + full history export**
- **Import**: "IMPORT EXCEL" button on Roster (hidden `<input type="file">` + `FileReader` + `XLSX.read`) parses the "Roster" sheet using the same headers `exportRosterExcel()` produces, upserts by ID (creates a new id if blank/unmatched), and shows an added/updated summary both as a notification and an inline banner. Verified round-trip in QA: exported 143 rows, edited one field + appended a blank-ID new-hire row, reimported → "1 added, 143 updated" and the new hire appeared correctly in the roster.
- **Full history export**: "EXPORT FULL HISTORY (EXCEL)" button on Archive builds one workbook covering every saved shift: "All Boards" (flattened entries + Date/Side, reusing/generalizing `exportExcel`'s row shape), "All Deficiencies", "All Redistributions", and "Shift Summary" (one row per shift, including `ManualEntry`/`Justification`/`FuturePending`/`ComplianceChecks` columns). Verified: 4 sheets present, row counts and field values (including a `deficiency_assignment` override row) all correct.

**§17 — Roster bulk selection + management actions**
- A checkbox per roster row (independent of per-field edit controls, admin-only). When ≥1 selected, a bulk action bar appears: **Set Active**, **Set Inactive**, **Mark Agency**, **Unmark Agency**, **Export Selected (Excel)**, and **Delete Selected**. Selection clears after any bulk action. Delete Selected is gated by an **in-app confirm dialog** (styled modal, not native `confirm()`) per spec.

**§18 — Zone/category color visualization**
- `ZONE_COLORS` map (new hues `plum`/`rose`/`ochre`/`steel`/`moss`/`clay` added to the `C` palette, kept muted/tasteful) keyed by the exact `category` field values listed in the spec (Gold, Gold A, Green A, Green B, Flow, Triage, Trauma, Observation, Tech Zone, HUC, Special, B-Bed).
- Applied as a colored left-border accent + small colored dot on each entry row on the Generated Board preview and the Current Shift / Archive-detail entry lists. A `<ZoneLegend/>` component renders the full 12-category legend under each of those panels.

**§19 — Pending/future boards**
- `savePending()` tags a saved shift `futurePending:true` when `pending.date > today` (string comparison). The Archive tab renders a distinct **"PENDING"** section above the closed-shift list for all shifts where `futurePending===true && !eod?.closed`.
- Pending shifts are rendered via a new shared `CurrentShiftDetail` wrapper component (header panel with EXPORT/CLOSEOUT + `CurrentShiftEntries`) — the exact same component used for a same-day open Current Shift — so redistribute/hold/combine/boarder/compliance-check controls all work identically on a future board. The Current Shift tab's "CURRENT SHIFTS" list explicitly excludes `futurePending` shifts (`!s.futurePending`) so a pending board only ever shows under Archive until closed, at which point it moves to the normal closed list (verified end-to-end in QA).

**§20 — Monthly-synced rotation window**
- New `rotationMonthKey(dateStr, side)` → `"YYYY-MM"` and `sameRotationPeriod(refDate, refSide, rowDate, rowSide)` predicate, replacing the `daysBetween(...)<=config.rotation_window_days` check inside `runEngine`'s `win` filter.
- `rotation_window_days` is kept in `DEFAULT_CONFIG`/data model for backward compatibility but is no longer read by the engine; removed from the visible Config form and replaced with an explanatory note. The header's staff/window summary line now reads "monthly rotation window (YYYY-MM)" instead of "Nd window".
- Night+month-boundary exception: documented inline in `rotationMonthKey` — see Assumption 3 for the precise interpretation used.

## Cross-cutting notes followed
- Everything still lives inside the single-file architecture — new logic is either inside `RotationEngineV4` or in well-named module-level helper functions/components (`recomputeDeficiencies`, `DeficiencyAssignRow`, `SortableRosterHeader`, `sortRosterEntries`, `defaultRosterSort`, `CurrentShiftDetail`, `ZONE_COLORS`/`zoneColor`/`ZoneLegend`, `rotationMonthKey`/`sameRotationPeriod`). No build step, no bundler, no new npm dependency.
- Hoisted the previously component-local `match()` search helper to module scope so `CurrentShiftEntries`' §13 mid-shift CLOSE ASSIGNMENTS control (a module-level component) can use it too — this was a mechanical refactor, not a behavior change.
- No new persisted top-level collection was needed — §11/§19 both extend the existing `shifts` records with new fields (`manual_entry`, `justification`, `futurePending`, `complianceChecks`, `closed_assignments_ids`) saved via the existing `sSet(KEYS.shifts, ...)` path. §13's mid-shift room closures and §14's sort state are intentionally kept as component/app-local `useState`, not persisted (see Assumptions 2 and 4).
- Footer precedence text updated: replaced "rotation window" wording with "calendar-month rotation window" and added a sentence noting that §12 deficiency-review assignments and §11 manual/historical entries are operator-applied and sit outside the automated precedence chain.

## Bug found and fixed during QA
**Stale-closure race in the Current Shift deficiency-assign flow (§12/§13).** The first implementation of `assignShiftDeficiency` read `shifts` from its enclosing closure, called `setShifts(u)` with the new entry appended, then deferred `runComplianceCheck(shiftId)` via `setTimeout(...,0)` to refresh the panel. `runComplianceCheck` *also* read `shifts` from its own closure — which, depending on React's batching/timing, was still the **pre-update** array — and its own `setShifts(u)` call (spreading the stale shift and only adding a `complianceChecks` log entry) clobbered the just-added entry. Net effect: clicking ASSIGN appeared to work for an instant (entry count 32→33) and then silently reverted (back to 32) within ~100–200ms, with no console error, making the bug easy to miss on a single quick screenshot.
- **Fix**: rewrote both `runComplianceCheck` and `assignShiftDeficiency` to use the **functional** `setShifts(prev => ...)` form throughout, and had `assignShiftDeficiency` compute its own fresh deficiency list synchronously from the entries it just computed (via the returned `saved` array from the functional updater) instead of a separate deferred call that could race. Re-verified via direct `localStorage` state inspection immediately after the click and after a 200ms wait — entry now persists correctly, and the compliance panel correctly drops the resolved deficiency.
- This is the one functional bug found in the whole Phase 2 pass; everything else worked on first pass in QA.

## Assumptions made
1. **§12's REASSIGN-for-a-flagged-entry extension**: the spec says the same assign+comment control should "also work as REASSIGN for any currently-assigned staff member from the deficiency context (e.g. reassigning someone off a flagged wildcard/override entry)". I implemented the ASSIGN half fully (fills `unfilled` gaps, reused identically on the unsaved board and Current Shift), but did not build a second reassign-specific control for wildcard/override-flagged deficiency rows in this pass — `DeficiencyAssignRow` explicitly returns `null` for non-`unfilled` kinds. An operator can still reassign a flagged wildcard/override staff member today via §9's existing RELEASE + reassign flow on Current Shift, or via §15's inline dropdown on the unsaved board; there just isn't a *second* entry point directly from the deficiency-list row itself yet.
2. **Mid-shift room closures are not persisted per-shift**: `midShiftClosed` is `RotationEngineV4`-local `useState`, keyed by shift id, not saved into the `shifts` record. This matches how `closed`/`closedSet` work for board-generation-time closures (also local state, only persisted indirectly via `closed_assignments_ids` at save time). A page reload loses in-progress mid-shift closures for an open shift; re-closing takes one click and is idempotent. If persistence across reloads/devices is required, `midShiftClosed` should be folded into the shift record with a `sSet` call in `toggleRoomClosure`, mirroring `updateEOD`.
3. **§20 night+month-boundary exception**: interpreted literally per the spec's own reasoning — since a shift's `date` field always records its *start* date (never a rollover date), attributing that shift's entries to the month `rotationMonthKey(dateStr, side)` derives from `dateStr` **already** satisfies "attribute to the previous month" for a night shift starting on the last day of a month, because `dateStr` itself is in that (correct, previous-relative-to-the-rollover) month. No separate roll-back arithmetic was needed in the common case; the exception only becomes observable if some other code path ever attributes a row to the *rollover* date instead of the shift's start date, which nothing in this codebase does. Documented at length inline in `rotationMonthKey` rather than silently doing nothing, since this was a deliberate interpretation call.
4. **`sortBy`/`sortDir` are global app state, not per-shift**: a single pair of `sortBy`/`sortDir` state variables drive sorting on both Current Shift and Archive detail (and any Pending board), rather than one independent sort state per open shift. This matches "clickable column headers" as a single reusable control and is simpler, at the cost of the sort selection carrying over when you switch which shift/board is open — judged a reasonable, minor UX tradeoff rather than a spec violation (spec does not require independent per-shift sort memory).
5. **Manual historical board's per-row start time**: the spec doesn't specify a start time for manually backfilled rows, so `saveManualHistoricalBoard` defaults every row to the side's standard start (`07:00` day / `19:00` night), matching the same default used elsewhere in the app (predetermined/deficiency-assignment entries).
6. **`recomputeDeficiencies()` is a strict superset entry point**: rather than duplicate `computeDeficiencies()`'s logic for the §13/§15 "live edit" cases, I added one small wrapper (`recomputeDeficiencies`) that derives `core`/`used`/`secondaryIds` from a live `entries[]` array + `catalog` + `closedIds`, then delegates to the existing `computeDeficiencies()`. This is the "shared helper" the Phase 1 notes explicitly flagged as forward-compatible groundwork; I did not change `computeDeficiencies()`'s signature or behavior, only added a way to call it without first running `runEngine`.
